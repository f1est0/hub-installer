# HubSentry для владельцев VDS и серверов

HubSentry — сервис мониторинга, который помогает владельцу VDS, Raspberry Pi или проекта вовремя узнать о проблеме.

Сейчас проект находится в закрытом тестировании. Возможности, условия доступа и интерфейс ещё могут меняться.

Сайт хаба: https://uptime.profium.pro/

## Что вы получаете

После подключения проекта в хабе появляется его карточка и уведомления в Telegram или MAX:

- сервер или сайт перестал отвечать;
- пропал heartbeat от проекта или агента;
- закончился или скоро закончится SSL-сертификат;
- закончился срок регистрации домена;
- не выполнился бэкап, импорт или другая задача по расписанию;
- приложение отправило ошибку;
- на сервере закончились место, память или другие ресурсы;
- остановился Docker-контейнер или системная служба;
- появились важные ошибки в журналах.

Хаб хранит историю сигналов и показывает доступность, простои и основные показатели за период.

## Что отслеживается на VDS

Для этого устанавливается агент мониторинга. Он раз в несколько минут отправляет в хаб:

- загрузку CPU, среднюю нагрузку, память и swap;
- заполненность дисков, inode, температуру и сетевые ошибки;
- состояние Docker-контейнеров, объём Docker-логов и использование места;
- доступность и состояние системных служб;
- ошибки в системном журнале;
- необходимость обновлений и перезагрузки;
- доступность SSH, настройки firewall и отдельные признаки безопасности;
- состояние веб-сервера по логам, если это настроено;
- состояние подключённых баз данных: PostgreSQL, MySQL/MariaDB, Redis, MongoDB, ClickHouse, Elasticsearch/OpenSearch.

Также можно настроить проверку внешних адресов и свежести файлов бэкапов.

## Что передаётся в хаб

Агент передаёт только технические показатели и статусы, необходимые для мониторинга:

- числовые метрики и состояния сервисов;
- имена контейнеров, служб и баз данных;
- количество ошибок и краткие строки из журналов;
- время последнего запуска задач и размер результата бэкапа;
- статусы сертификатов, доменов и внешних проверок.

Хаб не получает содержимое файлов, исходный код, пароли, токены, тексты запросов к базам и пользовательские данные. Не добавляйте секреты в сообщения об ошибках и дополнительные поля.

Запросы агента идут на `https://uptime.profium.pro` по HTTPS. Если хаб временно недоступен, это не ломает ваш проект: клиент использует ограниченный таймаут и продолжает работу отдельно.

## Подключение проекта

Владелец хаба выдаёт:

- адрес хаба `HUB_URL`;
- отдельный токен проекта `HUB_TOKEN`.

Токен — это секрет проекта. Храните его в переменных окружения или `.env`, не коммитьте в Git и не отправляйте в чаты.

Подключить можно:

- **VDS целиком** — установить агент;
- **приложение** — добавить heartbeat и отправку ошибок;
- **cron или бэкап** — запускать heartbeat/job из shell;
- **любой другой сервис** — отправлять сигналы по HTTP API.

### Установка агента на VDS

Скачайте публичный загрузчик из репозитория и запустите от root:

```bash
sudo sh hub-install.sh
```

Загрузчик проверяет токен, подпись выпуска и контрольные суммы файлов. Агент устанавливается с ограниченными правами, токен хранится отдельно, обновления проверяются автоматически.

Публичный репозиторий загрузчика: https://github.com/f1est0/hub-installer

### Heartbeat приложения

Приложение может раз в минуту или пять минут отправлять сигнал «я жив»:

```bash
curl -fsS -X POST \
  -H "Authorization: Bearer $HUB_TOKEN" \
  "$HUB_URL/api/v1/heartbeat"
```

Если сигналы перестали приходить дольше заданного интервала, хаб отправит тревогу.

### Контроль задач и бэкапов

Для бэкапа, импорта или другой периодической задачи передаётся результат выполнения:

```bash
curl -fsS -X POST \
  -H "Authorization: Bearer $HUB_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"backup","status":"ok","durationMs":1200,"expectEveryS":86400}' \
  "$HUB_URL/api/v1/job"
```

Если задача не запускалась дольше ожидаемого времени или завершилась с ошибкой, владелец получает уведомление. При желании можно передавать размер бэкапа, чтобы заметить пустой или подозрительно маленький файл.

### Ошибки приложения

```bash
curl -fsS -X POST \
  -H "Authorization: Bearer $HUB_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"level":"error","message":"Не удалось выполнить оплату"}' \
  "$HUB_URL/api/v1/event"
```

Ошибки отправляются не чаще одного уведомления в минуту на проект, чтобы не создавать поток сообщений.

## Уведомления и пользователи

У каждого пользователя своя база проектов. Пользователь видит только свои проекты и показатели. Владелец хаба не получает доступ к содержимому вашего приложения, только к тем сигналам, которые вы отправили.

Приглашения новых пользователей сейчас выдаёт администрация центрального хаба. По приглашению пользователь получает отдельную область и может добавить свои проекты. Его проекты не смешиваются с чужими.

На этапе тестирования доступ предоставляется в рамках согласованных приглашений. Позже свободную выдачу приглашений отключат, а подключение пользователей будет переведено на платную модель.

Уведомления можно получать в Telegram или MAX. Подписчик публичной страницы статуса видит только доступность выбранного сервиса и не видит внутренние показатели сервера.

## Проверка после подключения

1. Запустите агент или приложение с `HUB_URL` и `HUB_TOKEN`.
2. Проверьте ответ:

```bash
curl -fsS -H "Authorization: Bearer $HUB_TOKEN" \
  "$HUB_URL/api/v1/status"
```

3. Убедитесь, что проект появился в карточке хаба.
4. При необходимости отправьте тестовую ошибку и проверьте уведомление.

## Важные ограничения

- Хаб работает на небольшом домашнем сервере, поэтому во время закрытого тестирования возможны изменения и перерывы.
- Если сам хаб потеряет интернет или питание, он не сможет отправить уведомление до восстановления связи.
- Лимит API — до 120 запросов в минуту на проект.
- Не передавайте в сообщениях, логах и дополнительных полях пароли, токены и персональные данные.
