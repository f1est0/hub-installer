# HubSentry

HubSentry — личный хаб мониторинга сайтов, серверов и фоновых сервисов.

Он собирает сигналы от подключённых проектов и сам проверяет доступность сайтов, доменов, SSL-сертификатов и опасных портов. Если объект перестал отвечать, сервер пропал, заканчивается сертификат или пришла ошибка, хаб отправляет уведомление в Telegram или MAX.

Сайт хаба: https://uptime.profium.pro/

Публичный загрузчик агента: https://github.com/f1est0/hub-installer

Основной исходный код хаба находится в закрытом репозитории. Ниже собраны инструкции, которые нужны пользователю для ознакомления и подключения.

## Подключение проекта к хабу

Хаб следит за состоянием проектов и пишет владельцу в Telegram, если что-то сломалось: проект перестал отвечать,
не выполнилась задача по расписанию (например, бэкап), в коде случилась ошибка.

Подключение занимает около 5 минут. **Ничего устанавливать не нужно**: клиент - один файл без зависимостей
(для Node/Next.js, Python и shell/cron).

## Что вы получаете от владельца хаба

| Что | Пример |
| --- | --- |
| Адрес хаба `HUB_URL` | `https://uptime.profium.pro` |
| Токен проекта `HUB_TOKEN` | `hub_AbC…` (секрет проекта, как пароль) |

Токен выдаётся на один проект. Храните его в переменных окружения или `.env`, **не коммитьте в Git** и не отправляйте
в чаты. Если токен утёк, владелец выпускает новый, старый перестаёт работать.

## Что отправлять (три вида сигналов)

1. **Heartbeat** - «я жив», раз в минуту. Если сигналов нет дольше 1,5 интервала, придёт тревога
   (интервал владелец задаёт при создании проекта, обычно 5 минут).
2. **Задача по расписанию** (`job`) - бэкап, cron, импорт. Сообщайте результат: успех или сбой с текстом.
   Если задача не выполнялась дольше ожидаемого (`expectEveryS`), придёт тревога «задача пропущена».
3. **Ошибка** (`event` уровня `error`) - исключение из кода. В Telegram приходит не чаще раза в минуту на проект.
   Уровни `info` и `warn` только сохраняются в истории.

## Node.js / Next.js

Скопируйте `clients/node/hub-client.mjs` в проект (например, `lib/hub-client.mjs`) и задайте `HUB_URL`, `HUB_TOKEN`.

```js
import { createHub } from "./lib/hub-client.mjs";
const hub = createHub();

hub.startHeartbeat();          // «я жив» раз в минуту
hub.captureProcessErrors();    // необработанные ошибки уходят в хаб

// Задача по расписанию: сообщит об успехе или сбое и пробросит исключение дальше
await hub.job("backup", () => makeBackup(), { expectEveryS: 86400 });

await hub.error(new Error("Не удалось списать оплату"), { orderId: 42 });
```

**Next.js (15 и новее):** положите `clients/node/next-instrumentation.example.ts` в корень проекта (или в `src/`) как
`instrumentation.ts`. Он включает heartbeat и отправляет ошибки серверных компонентов, route handlers и server actions
(через `onRequestError`). Больше ничего менять не нужно.

## Python

Скопируйте `clients/python/hub_client.py` в проект. Нужен Python 3.8+, зависимостей нет.

```python
import logging
from hub_client import Hub

hub = Hub()                       # читает HUB_URL и HUB_TOKEN из окружения
hub.start_heartbeat()             # фоновый поток, раз в минуту
hub.capture_exceptions()          # необработанные исключения (в том числе в потоках)
logging.getLogger().addHandler(hub.logging_handler())   # все logging.error(...) уходят в хаб

with hub.job("backup", expect_every=86400):   # или декоратор @hub.job("backup")
    make_backup()

hub.error("Не удалось списать оплату", {"order": 42})
```

## Shell / cron (любой язык)

Скопируйте `clients/shell/hub.sh`. Нужны только `sh` и `curl`.

```cron
## Подключение проекта к хабу
15 3 * * *  HUB_URL=https://uptime.profium.pro HUB_TOKEN=hub_xxx  sh /opt/hub.sh run backup --every 86400 -- /opt/backup.sh

## Подключение проекта к хабу
* * * * *   HUB_URL=https://uptime.profium.pro HUB_TOKEN=hub_xxx  sh /opt/hub.sh heartbeat
```

`hub.sh run` возвращает код вашей команды, а при сбое отправляет последние строки её вывода.

## Размер бэкапа (необязательно, но полезно)

Если вместе с результатом задачи передать размер файла, хаб запоминает «обычный» размер и предупреждает, когда новая
копия меньше половины обычного или пустая. Так видно, что бэкап «выполнился», но на самом деле сломан.

```js
// Node: число или функция, получающая результат вашей функции
await hub.job("backup", makeBackup, { expectEveryS: 86400, sizeBytes: (path) => fs.statSync(path).size });
```
```python
## Подключение проекта к хабу
with hub.job("backup", expect_every=86400) as job:
    path = make_backup()
    job.size_bytes = os.path.getsize(path)
```
```sh
## Подключение проекта к хабу
sh hub.sh run backup --every 86400 --size-file '/backups/db-*.sql.gz' -- /opt/backup.sh
```

## Сервер целиком: агент состояния

Чтобы хаб следил за самой машиной (диск, память, процессор, Docker, службы, логи, безопасность, базы данных, веб-серверы), на неё ставится агент
`hub-agent.sh`. Владельцу сервера отдаётся один файл `hub-install.sh` с инструкцией
(см. раздел «Установка агента» в этом файле):

```bash
sudo sh hub-install.sh       # меню: ввести токен (он сразу проверяется), установить, включить автообновление
```

Агент заодно служит сигналом «я жив»: для такого проекта владелец хаба ставит `--heartbeat 900`. Что именно агент
собирает, когда приходят уведомления и что не отправляется: см. раздел «Агент сервера» в этом файле.

Владелец хаба может дополнительно попросить агента:
- проверять, достаёт ли сервер внешние адреса: `/set код --reach max.ru:443,api.telegram.org`;
- следить за свежестью бэкапов в папке: `/set код --fresh /var/backups/db:26h` (проще, чем встраивать `hub.sh` в скрипт
  бэкапа, если нужен только факт «файл свежий»). С агентом v10 хаб заодно проверяет, что самый новый файл читается (архив, дамп PostgreSQL), и сообщает о повреждённом;
- смотреть базы данных в контейнерах: PostgreSQL, MySQL и MariaDB, MongoDB, ClickHouse, Elasticsearch и OpenSearch, Redis находятся сами (в контейнерах Docker и на самом сервере), экран `/bd_код`; запросы к nginx и Caddy (доля 5xx, время ответа) считаются из их логов, для Caddy нужен лог доступа в файле `/var/log/caddy/*.log` или в выводе контейнера.

## Сертификат и домен (настраивает владелец хаба)

Если у проекта задан `--url` с https, хаб сам проверяет сертификат сайта раз в 6 часов и пишет за 14, 7, 3 и 1 день до
окончания, а также если сертификат недействителен (не тот домен, самоподписанный, не доверенный). Срок регистрации
домена отслеживается, если владелец указал `--domain` (проверка раз в сутки). Разработчику для этого ничего делать
не нужно.

## Любой другой язык: чистый HTTP

```bash
curl -fsS -X POST -H "Authorization: Bearer $HUB_TOKEN" $HUB_URL/api/v1/heartbeat
curl -fsS -X POST -H "Authorization: Bearer $HUB_TOKEN" -H "Content-Type: application/json" \
     -d '{"name":"backup","status":"ok","durationMs":1200,"expectEveryS":86400}' $HUB_URL/api/v1/job
curl -fsS -X POST -H "Authorization: Bearer $HUB_TOKEN" -H "Content-Type: application/json" \
     -d '{"level":"error","message":"Текст ошибки"}' $HUB_URL/api/v1/event
curl -fsS -H "Authorization: Bearer $HUB_TOKEN" $HUB_URL/api/v1/status      # текущее состояние проекта
```

| Метод и путь | Тело (JSON) |
| --- | --- |
| `POST /api/v1/heartbeat` | пустое |
| `POST /api/v1/job` | `name` (строка ≤64), `status` (`ok`/`fail`), необязательно: `message`, `durationMs`, `expectEveryS` (30…7776000), `sizeBytes` (размер результата, например бэкапа) |
| `POST /api/v1/event` | `message` (≤2000), `level` (`info`/`warn`/`error`), необязательно `meta` (объект) |
| `POST /api/v1/metrics` | показатели сервера, их формирует `hub-agent.sh`; поля по версиям агента в см. раздел «Агент сервера» в этом файле |
| `GET /api/v1/config` | - (агент получает списки `reach` и `fresh`, заданные владельцем хаба) |
| `GET /api/v1/status` | - |

Ответы: `200` успех, `400` неверные данные, `401` неверный токен, `413` тело больше 16 КБ, `429` слишком часто
(не больше 120 запросов в минуту на проект).

## Проверка, что всё подключено

1. Запустите проект с заданными `HUB_URL` и `HUB_TOKEN`.
2. Выполните `curl -fsS -H "Authorization: Bearer $HUB_TOKEN" $HUB_URL/api/v1/status`: в ответе должно быть
   `"heartbeat":{"state":"ok",…}`.
3. Попросите владельца отправить `/status` боту: проект должен быть зелёным (🟢).
4. Отправьте тестовую ошибку (`hub.error(new Error("тест"))`): владелец получит сообщение.

## Что клиенты гарантируют

- Недоступность хаба **не ломает проект**: клиенты не бросают исключений и ограничивают запрос таймаутом 5 секунд.
- Если `HUB_URL` или `HUB_TOKEN` не заданы, клиент молча отключается (один раз пишет предупреждение в лог).
- Хаб получает только то, что вы явно отправили. Не кладите в сообщения и `meta` пароли, токены и персональные данные.

## Что уточнить у разработчика перед подключением

- Как часто проект должен присылать сигнал? (Чем реже, тем меньше ложных тревог; обычно 5 минут.)
- Какие регулярные задачи есть (бэкап, импорт, рассылка) и как часто они запускаются?
- Есть ли публичный адрес для проверки доступности (например, `/health`)? Хаб может сам обращаться к нему раз
  в минуту: так видно, что сайт реально отвечает, даже если сам проект ничего не отправляет.
- На чём написан проект (Node, Next, Python, другое) и где запущен (Docker, systemd, cron)?

## Команды Telegram-бота

Бот отвечает только владельцу в личном чате (аккаунты задаются в `TELEGRAM_CHAT_IDS`), остальным молчит. Те же
подсказки есть в самом боте: `/help` и справка по каждой команде (`/help_set`, `/help add` и т. д.). Если вызвать
команду без аргументов (например, просто `/add`), бот покажет её инструкцию.

**Нажимаемые команды.** В списках у каждого проекта есть ссылка вида `/p_garage_bot`: нажмите, и откроется карточка
проекта (дефисы в коде заменены на `_`, потому что Telegram не делает команды с дефисом нажимаемыми). Так же работают
`/u_код` (доступность и простои), `/c_код` (настройки) и `/help_команда` (справка).

**Один экран вместо ленты.** Карточки, списки, графики и справка (экраны) сменяют друг друга: новый экран приходит, а прошлый и набранная команда пропадают из чата. Внизу экрана есть нажимаемая строка «Назад»: из карточки проекта `/status`, из графика, доступности и настроек `/p_код`, из подробной справки `/help`. Ответы с токеном, кодом приглашения и подтверждения остаются в чате, их бот не убирает. Тревоги тоже не убираются.

**Значки:** 🟢 в порядке · 🟡 нужно внимание (мало места, скоро истекает срок, нужна перезагрузка) · 🔴 сбой ·
⚪ данных ещё нет · ⏸ мониторинг на паузе · 🔕 уведомления отключены.

## Смотреть

### /status - все проекты

Счётчики по состояниям, затем проекты по группам:
- **🖥 Серверы.** Группа по адресу, с которого проект присылает данные. Строкой сервера служит проект с агентом;
  остальные проекты на том же адресе идут веткой под ним (`├`, `└`).
- **🏠 Raspberry с хабом.** Проекты на самом Pi.
- **🌐 Сайты и сервисы.** Проекты без сервера, их хаб проверяет по адресу.

У проблемных проектов под строкой написано, что не так (`↳ нет сигнала 12 мин`). Проблемные группы и проекты идут выше.

### /project код - карточка проекта

Открывается и нажатием на `/p_код` в любом списке. Разделы показываются, только если в них есть данные:

| Раздел | Что внутри |
| --- | --- |
| ⚠️ Требует внимания | все текущие проблемы проекта |
| 📈 Ресурсы | полоски процессора, памяти и дисков (⚠️ выше порога), температура, время работы, скорость сети; ниже строка «За сутки» (среднее и пик, изменение диска, трафик) |
| 🐳 Контейнеры | сколько работает; упавшие, нездоровые и на паузе; три самых тяжёлых по памяти |
| 📡 Проверки | сигнал «жив», адрес сайта и время ответа, сертификат, домен, доступ с сервера (`--reach`), свежесть файлов (`--fresh`), ошибки в логах, сертификаты на сервере, доступность за 7 и 30 дней |
| 🧾 Сервер | число задач cron и пользователи, которые могут войти, зомби-процессы, ошибки сети, большие логи Docker; запросы к веб-серверу за 5 минут (доля 5xx, p95); ссылка `/bd_код`, если на сервере есть базы |
| 🛡 Безопасность | вход по SSH, файрвол, открытые порты и результат проверки снаружи, обновления |
| ⏱ Задачи | результат последнего запуска, размер бэкапа, текст ошибки |
| 🕘 Последние события | пять последних событий проекта |
| ℹ️ Подробнее о сервере | свёрнутый блок (нажмите, чтобы открыть): система и ядро, нагрузка, iowait, steal, самые прожорливые программы, место Docker, ключи SSH, sudo, версия агента |

Если агент на сервере старой версии, в карточке строка «🧩 есть v10: обновите».

### /projects (или /list) - все проекты списком

По проекту одна-две строки: сайт, сколько дней осталось у сертификата (🔒) и домена (🌍), когда был последний сигнал
(📡), проблемы. Если проектов много, список приходит несколькими сообщениями.

### /domains - сроки сертификатов и доменов

Все сертификаты (проекты с https-адресом, домены из `/domain`, сертификаты из `/cert`) и домены, ближайшие к
истечению сверху: 🟢 больше 14 дней · 🟡 14 и меньше · 🔴 7 и меньше, истёк или недействителен · ⚪ ещё не проверен.
Внизу подсказки `/set код --domain имя` для проектов, у которых домен не задан (проверьте их: подсказка строится по
имени сайта).

### /uptime - доступность и простои

```
/uptime              все проекты: доля времени без простоев за 7 и 30 дней, проблемные сверху
/uptime код          один проект (или нажмите /u_код): за 1, 7 и 30 дней и список простоев
/uptime код 90       простои за другой период (до 365 дней)
```

Простой: у проекта не было сигнала дольше допустимого (`--heartbeat`) или не отвечал адрес (`--url`). Если оба
случились одновременно, время не считается дважды. 🟢 от 99,9% · 🟡 от 99% · 🔴 ниже · ⚪ нечего считать.

### /chart - графики сервера

```
/chart код           за 24 часа (столбик - 1 час), то же нажатием /g_код (ссылка внизу карточки сервера)
/chart код 7d        за 7 дней (столбик - 6 часов), то же /gw_код
```

Графики текстом из символов `▁▂▃▄▅▆▇█` по истории показателей агента: процессор (у старых агентов нагрузка),
память, диск, температура, входящий и исходящий трафик, CPU steal (если был заметен). У каждого среднее и пик, под
графиками шкала времени. Память и диск на шкале 0-100%; у процессора и steal шкала подбирается по пику (до 10, 25, 50
или 100%) и указана в заголовке. `·` значит, что за этот отрезок сервер не присылал показатели.

Почему текстом, а не картинкой: через текущий прокси к Telegram проходят только текстовые сообщения (`sendPhoto` он не
пропускает), а текстовые графики будут работать и в MAX.

### /bd - базы данных сервера

```
/bd код              базы сервера, то же нажатием /bd_код (ссылка внизу карточки)
/bd                  у каких серверов есть базы
```

Агент находит базы данных в контейнерах Docker и на самом сервере и присылает только числа. PostgreSQL: подключения из максимума, размер, основной сервер или реплика и её отставание, долгие запросы (дольше 5 минут), блокировки. MySQL и MariaDB (агент версии 11): подключения, выполняющиеся запросы, размер, состояние и отставание репликации. MongoDB: подключения, размер, состояние участника набора реплик. ClickHouse: подключения, запросы, размер, отставание и режим «только чтение» у реплик. Elasticsearch и OpenSearch: статус кластера (зелёный, жёлтый, красный), узлы, нераспределённые шарды. Redis и Valkey: клиенты, память от лимита, успех сохранения на диск, связь реплики, отклонённые подключения. Если агент не смог подключиться без пароля, на экране «нет доступа» без тревоги. Данные и тексты запросов с сервера не уходят. Тревоги описаны в см. раздел «Агент сервера» в этом файле.

### /dns - DNS-записи

Последние известные записи отслеживаемых имён: A, AAAA, NS, MX для доменов, A и AAAA для адресов сайтов, TXT для
SPF, DMARC и DKIM. Хаб проверяет их раз в час; если запись изменилась и следующая проверка это подтвердила, приходит
сообщение со старым и новым значением. Сбой DNS-сервера изменением не считается.

### /mailcheck - почтовая защита

```
/mailcheck               коротко по всем отслеживаемым доменам
/mailcheck домен         подробно: MX, SPF, DMARC, DKIM, с советами
/mailcheck домен хост:порт   то же и сертификат почтового сервера
```

### /config код - что настроено у проекта

Открывается и нажатием на `/c_код` (внизу карточки проекта). По разделам «Сигнал», «Сайт и домен», «Проверки на
сервере» каждая проверка отмечена: ✅ включена (со значением) или ⚪ нет, и у выключенных готовая команда `/set`, как её
включить (нажатие на команду копирует её). Ниже задачи, паузы с командой, как снять паузу, и одна команда `/set …`,
которая повторяет все настройки (например, для другого проекта). Проверки на сервере предлагаются, только если на нём
стоит агент. Токен не показывается. То же: `/settings код`.

## Настроить

### /add - добавить проект

```
/add код "Название" [--heartbeat сек] [--url адрес] [--check сек] [--match "слово"] [--slow мс] [--domain имя]
```

| Параметр | Что это | Значения |
| --- | --- | --- |
| `код` | короткое имя проекта для команд | 2-32 символа: строчные латинские буквы, цифры, дефис. Например `shop-api` |
| `"Название"` | как проект называется в уведомлениях; с пробелами в кавычках | до 80 символов |
| `--heartbeat сек` | как часто проект обязан присылать «я жив»; тревога, если сигнала нет дольше 1,5 интервала + 10 секунд | 30-604800, обычно `300`; для сервера с агентом `900` |
| `--url адрес` | адрес, который хаб проверяет сам; тревога после двух неудач подряд (нет ответа за 10 секунд или 5xx). 401 и 403 считаются «жив» | http или https |
| `--check сек` | как часто проверять `--url` | 30-86400, по умолчанию 60 |
| `--match "слово"` | слово, обязательное на странице (ловит «сайт отвечает, но пустой») | 2-100 символов |
| `--slow мс` | порог медленного ответа: три проверки подряд дольше порога дают 🐢 | 100-120000 |
| `--domain имя` | срок регистрации домена: предупреждения за 14, 7, 3 и 1 день | зарегистрированный домен, например `example.com` |

Сертификат https-адреса хаб проверяет сам (раз в 6 часов): предупреждения за 14, 7, 3 и 1 день и если сертификат
недействителен.

После команды бот присылает **токен** проекта. Он показывается один раз: перешлите его разработчику лично и удалите
сообщение. Потерянный токен восстановить нельзя, только выпустить новый (`/token`). Задачи по расписанию
регистрируются сами при первом сигнале.

```
/add shop-api "Магазин (API)" --heartbeat 300
/add site "Сайт" --url https://site.ru/health --check 120 --domain site.ru
```

### /set - изменить настройки

```
/set код --параметр значение [--параметр значение …]
```

| Параметр | Значения |
| --- | --- |
| `--name` | новое название (с пробелами в кавычках) |
| `--code` | новый код проекта; токен и история сохраняются |
| `--heartbeat`, `--url`, `--check`, `--match`, `--slow`, `--domain` | как в `/add`; `off` выключает |
| `--reach` | адреса, которые **сервер** проекта должен уметь достать: `max.ru:443,api.telegram.org`. Порт по умолчанию 443 (проверка HTTPS), другие порты TCP. `@proxy` после адреса: проверять через прокси, заданный на сервере (пункт 9 установщика). Два неудачных замера подряд дают 🔴 с причиной. До 8 адресов, внутренние нельзя. Нужен агент v4 |
| `--fresh` | папки на сервере, где должен быть свежий файл (обычно бэкап): `/var/backups/db:26h,/srv/dumps:7d` (h часы, d сутки). Старый файл, пустая папка: 🔴; новый файл меньше половины прошлого: 🟡. До 8 папок, системные нельзя. Нужен агент v6 |
| `--maint` | окно обслуживания: `"вс 03:00-04:00"`, `"пн-пт 02:00-02:30; сб,вс 03:00-05:00"` (без дней каждый день), `off` выключить. В окне тревог по проекту нет; если после окна проблема осталась, приходит одно сообщение со списком |
| `--public` | `on`: показывать проект на публичной странице статуса (`/statuspage`), `off`: убрать |
| `--open` | порты, открытые в интернет намеренно: `3129,8443`. О них хаб не тревожит при проверке опасных портов |

```
/set shop-api --heartbeat 600
/set zovio --reach max.ru:443@proxy,api.telegram.org
/set mvp --fresh /var/backups:26h
/set mvp --maint "вс 03:00-04:00"
/set blog --heartbeat off
```

После изменения бот показывает обновлённую карточку.

### /domain и /cert - домены и сертификаты без проекта

```
/domain add имя [--hosts сайт1,сайт2:порт]   срок регистрации домена (и сертификаты указанных хостов)
/domain remove имя
/domain                                      список доменов без проекта
/cert add хост[:порт]                        только сертификат (поддомен, почтовый сервер на своём порту)
/cert remove хост[:порт]
```

Сертификаты проверяются раз в 6 часов, домены раз в сутки. Для почты с прямым TLS указывайте порт:
`mail.ozfi.store:993`. Службы со STARTTLS (587, 143) так не проверяются. `/domain` показывает только эти домены,
`/domains` все сроки вместе с проектами.

### /digest - ежедневная сводка

```
/digest              настройка
/digest 08:30        время (по умолчанию 09:00, часовой пояс HUB_TZ)
/digest off | now    выключить | показать сейчас
```

Одно сообщение в день: счётчики, что требует внимания, сроки в ближайшие 30 дней, почтовая защита, ошибки за сутки.
Если хаб в это время был выключен, сводка придёт после запуска.

### /monthly - доступность за месяц

1-го числа в 09:10 одно сообщение: доступность каждого проекта с проверками за прошлый месяц (худшие сверху), число и длительность простоев, с прошлым месяцем для сравнения. `/monthly` показывает отчёт сейчас, `/monthly off` и `/monthly on` выключают и включают его (вместе с итогами для подписчиков).

### /weekly - недельный отчёт

```
/weekly              настройка
/weekly now          показать сейчас
/weekly пн 09:00     день и время (пн, вт, ср, чт, пт, сб, вс); /weekly 10:30 меняет только время
/weekly off          выключить
```

Раз в неделю (по умолчанию в понедельник в 09:05, после ежедневной сводки) одно сообщение с итогами недели:
- сколько было простоев и их общая длительность, сколько ошибок прислали проекты, и то же за прошлую неделю;
- доступность проектов, у которых она была ниже 100%, с прошлой неделей для сравнения (если проект в прошлую неделю
  наблюдался хотя бы 3 дня), остальные одной строкой;
- три проекта, приславшие больше всего ошибок;
- каждый сервер с агентом: средняя и пиковая загрузка процессора и памяти, как изменился диск. Если диск растёт
  (от 0,05% в сутки), прогноз: «диск растёт на 0,4% в сутки: 95% примерно через 37 дн.» (по часовым замерам за неделю);
- сертификаты и домены, истекающие в ближайшие 30 дней;
- что требует внимания прямо сейчас.

Первый запуск отчёт задним числом не шлёт. Если хаб в назначенное время был выключен, отчёт придёт после запуска
в тот же день.

### /remind - напоминания о нерешённых проблемах

`/remind 3` напоминать каждые 3 часа (1-72, по умолчанию 6), `/remind off` не напоминать. Напоминаются только сбои 🔴.

### /web - закрытая веб-панель

```
/web         одноразовая ссылка для входа (5 минут) и список активных входов
/web off     завершить все входы
```

Панель в браузере по адресу `адрес-хаба/panel`, видна только вам. В ней обзор всех серверов и проектов (со
статусом, полосками процессора, памяти и диска, проблемами) и страница проекта: настоящие графики за 24 часа и 7 дней,
карточка, доступность за 90 дней и настройки (то же, что в боте; команды вроде `/p_код` там ссылки).

Вход: бот присылает одноразовую ссылку, на странице по ней нужно нажать «Войти» (так предпросмотр ссылки в
мессенджерах её не тратит). Вход запоминается на этом устройстве на 30 дней. В базе хранятся только хэши ссылок и
сессий, cookie недоступна скриптам и уходит только по HTTPS на этот сайт; без входа панель показывает только просьбу
отправить боту `/web`. Если открывали панель на чужом устройстве, отправьте `/web off`.

### /server - имена серверов

```
/server                                 серверы (адреса) и проекты на каждом
/server name 89.125.117.47 "Helsinki"   задать имя по адресу
/server name mvp "Helsinki"             то же по коду любого проекта на этом сервере
/server name 89.125.117.47 off          сбросить имя
```

Сервер в хабе - это адрес, с которого проекты присылают данные. Без имени в `/status` сервер показан проектом, на
котором стоит агент. С именем - отдельной строкой «Helsinki · 89.125.117.47», а все проекты этого сервера (первым
проект с агентом) веткой под ней. Имя видно и в карточке проекта («сервер Helsinki (89.125.117.47)»), и в недельном
отчёте. Имя привязано к адресу: если сервер сменит IP, задайте его заново.

### /statuspage - публичная страница статуса

**Подписка клиентов на сбои.** Внизу страницы есть ссылки «Узнавать о сбоях» на общего бота хаба в Telegram и MAX. Клиенту не нужен код приглашения: он нажимает ссылку, и бот пишет ему, только когда сервис со страницы перестал работать и когда снова заработал (во время окна обслуживания не пишет), а 1-го числа присылает итоги доступности за месяц. Внутренние проблемы серверов подписчики не видят. Отписаться: `/unsubscribe` в боте. Если подписчик заблокировал бота, он отписывается сам. Сколько подписчиков, показывает `/statuspage`.

Страница для клиентов по секретному адресу вида `https://адрес-хаба/status/k3m9x2q7wd4f` (и `.json` на конце для
программ). Пароля нет, но адрес не угадать: страницу видят только те, кому вы дали ссылку, в поисковики она не
попадает. Общий `/status` отвечает 404. Адрес показывает `/statuspage`.
На ней общий баннер («Все сервисы работают» или «Есть сбои»), у каждого сервиса состояние, полоса доступности за 90
дней (каждый день отдельным блоком: зелёный от 99,9%, жёлтый от 99%, красный ниже, серый нет данных) и процент, ниже
простои за 14 дней. Страница без пароля и без скриптов, сама обновляется раз в минуту, в тёмной и светлой теме.

```
/set код --public on            показать проект на странице (off убрать)
/statuspage                     адрес и что сейчас на странице
/statuspage title "Моя компания"     заголовок страницы
/statuspage newlink             новый адрес, если старый утёк (старый сразу перестаёт работать)
```

На страницу попадают только проекты, отмеченные явно. Состояние считается только по доступности: открыт ли простой
(нет сигнала или адрес не отвечает). Внутренние проблемы серверов (диск, память, безопасность, опасные порты), адреса
сайтов и IP на странице не показываются никогда. Ссылку в боте даёт переменная `HUB_PUBLIC_URL` в `.env`.

### /quiet - тихие часы

`/quiet 00:00 08:00`: в этом интервале предупреждения 🟡 копятся и после окончания приходят одной сводкой; сбои 🔴,
входы по SSH с нового адреса и новые открытые порты приходят сразу. `/quiet off` выключает.

Утренняя сводка сгруппирована по проектам: у каждого ссылка на карточку `/p_код`, ниже время и суть предупреждений. ✅ у
проекта значит, что к концу тихих часов всё уже вернулось в норму.

## Управлять

| Команда | Что делает |
| --- | --- |
| `/pause код` | пауза мониторинга проекта: проверок и тревог нет, в списках ⏸. `/resume код` вернуть; отсчёт ожидаемых сигналов начнётся заново |
| `/pause код задача` | пауза одной задачи (`/resume код задача`) |
| `/pause код контейнер [--note "подпись"]` | контейнер остановлен намеренно: тревоги нет, в карточке подпись «Остановлен администратором» или ваша |
| `/mute код минуты` | не присылать уведомления проекта (до недели); хаб продолжает следить, в списках 🔕. `/mute код off` включить |
| `/token код` | новый токен; **старый перестаёт работать сразу** |
| `/delete код confirm` | удалить проект со всей историей; без `confirm` только предупреждение |

То же из командной строки Pi:

```
sudo docker compose exec hub node src/cli.ts add shop-api "Магазин" --heartbeat 300
sudo docker compose exec hub node src/cli.ts list | token <код> | mute <код> <минуты|off> | delete <код>
```

## Команды администратора (только владельцу хаба)

Служебные команды не выводятся ни в меню бота, ни в общей справке `/help`: все они собраны в **`/admin_help`**. Пользователям хаба они недоступны (бот отвечает «только владельцу хаба»), а владельца бот узнаёт по Telegram-аккаунту из `TELEGRAM_CHAT_IDS`.

| Команда | Что делает |
| --- | --- |
| `/invite заметка` | новый одноразовый код приглашения |
| `/tenants` | список пользователей и сколько проектов из лимита |
| `/tenant N off`, `/tenant N on` | отключить или включить пользователя, данные сохраняются |
| `/tenant N limit 20` | лимит проектов |
| `/tenant N delete` | показывает, что будет стёрто, и просит подтверждение |
| `/tenant N delete yes` | **полностью удаляет** пользователя: проекты, историю, настройки, страницу статуса. Пользователю приходит сообщение, агенты его серверов перестают приниматься, использованный код приглашения гаснет. Если он снова напишет боту, тот попросит код приглашения |
| `/web`, `/web off` | закрытая веб-панель (описана выше) |
| `/server` | имена серверов (описана выше) |
| `/shutdown` | аварийно выключить Raspberry Pi: бот присылает одноразовый код (60 с), `/shutdown КОД` выключает |

Удаление необратимо: в ночных бэкапах данные пользователя остаются до 30 дней, потом исчезают вместе с ними.

## Что приходит само

Кроме ответов на команды, бот сам присылает:
- **тревоги и восстановление**: один раз при переходе в проблему и один раз при возврате в норму. Что проверяется на
  серверах с агентом, с порогами: см. раздел «Агент сервера» в этом файле;
- **мигающие задачи**: после 3 сбоев за час уведомления о задаче сворачиваются в почасовую сводку;
- **опасные порты из интернета**: 🛡 с подсказкой, как закрыть (обычно Docker публикует порт мимо ufw);
- **перерыв связи у самого хаба**: если у Pi пропадал интернет, после возвращения одно сообщение «у хаба не было
  интернета N мин»; пропущенные за это время сигналы тревогой не считаются;
- **ежедневную сводку** и **напоминания** (см. `/digest`, `/remind`).

Если Telegram недоступен, сообщения копятся в очереди и приходят позже с пометкой «отправлено с опозданием»
(старше суток отбрасываются).

## Хаб в MAX

Тот же общий бот хаба можно запустить в мессенджере MAX (VK). Он работает параллельно с Telegram: одна база, одни и те
же команды, у владельца и у пользователей. Прокси для MAX не нужен: сервера MAX доступны из России напрямую.

## Что нужно подготовить

1. **Организация в MAX для бизнеса.** Бота с доступом к API создаёт только подтверждённая организация (ИП или юрлицо).
   Откройте business.max.ru, войдите через Госуслуги или СберБизнес ID (руководитель или администратор), подтвердите
   организацию.
2. **Бот.** В кабинете, в разделе «Чат-боты», создайте бота (имя, описание, аватар). Бот уходит на модерацию, после
   одобрения в кабинете появляется **токен**. Правила площадки могут измениться: сверяйтесь с dev.max.ru.
3. **ID владельца.** Напишите новому боту `/id`: он ответит `max:<число>`. Это ваш аккаунт в MAX.

## Настройка хаба

В `.env` на сервере хаба:

```
MAX_BOT_TOKEN=…                          # токен бота из кабинета MAX
TELEGRAM_CHAT_IDS=123456789,max:987654   # через запятую: ваш Telegram и/или MAX (max:<число> из /id)
## Хаб в MAX
```

`HUB_SECRET_KEY` должен быть задан (как для пользователей хаба). Токен Telegram-бота нужен, только если хотите работать и
в Telegram. После изменения `.env` перезапустите хаб (`docker compose up -d`).

Адрес API: `platform-api.max.ru` с обычным сертификатом. В документации MAX упомянут и `platform-api2.max.ru`, но у него
сертификат российского удостоверяющего центра Минцифры, которому образ хаба не доверяет; используйте первый.

## Как это работает

- **Один бот, два мессенджера.** Аккаунты MAX хранятся как `max:<номер>`, чтобы не пересекаться с номерами Telegram.
  Один человек в Telegram и в MAX получается двумя разными пользователями хаба (у каждого своя база).
- **Владелец** определяется по аккаунту `max:<номер>` из `TELEGRAM_CHAT_IDS`: ему доступны `/admin_help` и все служебные
  команды, тревоги приходят и в MAX.
- **Приглашение.** `/invite` показывает две ссылки: на бота в Telegram и в MAX. В ссылке MAX уже вшит код
  (`https://max.ru/<бот>?start=КОД`): человек нажимает «Начать» и сразу подключён. Код можно прислать и обычным сообщением.
- **Оформление.** Предпросмотр ссылок отключён (карточка сайта под сообщением не нужна). Сообщения приводятся к разметке MAX: жирный, курсив, моноширинный, ссылки. Сворачиваемые блоки («Подробности» в карточках) показываются цитатой `<blockquote>`: она выделена, но не сворачивается, потому что сворачивания в MAX нет.
- **Меню команд** в MAX одно на всех, без `/mybot` и служебных команд владельца.
- **Свой бот** (`/mybot`) работает только в Telegram.
- **Лимиты MAX:** до 4000 знаков в сообщении (длинное делится на части) и не больше двух сообщений в секунду в один
  диалог (между частями хаб делает паузу).

## Известные ограничения

- **Тревоги, которые хаб присылает сам.** Правила MAX запрещают рассылки; хаб пишет только людям, которые сами запустили
  бота, о событиях их же проектов. Если площадка начнёт блокировать такие сообщения, тревоги останутся в очереди хаба
  (до суток), а в логах будет `MAX HTTP …`.
- **Нажимаемые команды.** В MAX текстовые `/p_код` не нажимаются, поэтому под сообщением хаб добавляет кнопки (callback). В списках подпись берётся из названия («🟢 Main VDS Profium»), а сама команда из строки убирается. В карточке проекта это короткие кнопки «📈 Сутки», «⚙️ Настройки», «📊 Доступность», а на сервере с базами данных ещё «🗄 Базы» (код проекта дописывается, только если в сообщении их несколько), а строки-подсказки («Графики: /g_… · настройки: /c_…», «… · за неделю: /gw_…», «карточка: /p_…») из текста убираются. В графиках это кнопки «📅 Неделя» или «📈 Сутки» и «📋 Карточка». Нажатие кнопки **заменяет** сообщение, в котором она стояла (список сменяется карточкой, карточка графиком), поэтому чат не засоряется; под ответами добавляется кнопка «◀️ Назад» с теми же правилами, что в Telegram: из карточки проекта она ведёт к списку (`/status`), из графика, доступности и настроек обратно к карточке, из подробной справки к общей. Если заменить сообщение не удалось, ответ приходит новым. Набранная вручную команда отвечает новым сообщением, как обычно. Не больше 24 кнопок, по две в ряд. Хаб принимает с кнопок только свои команды (`/p_`, `/u_`, `/c_`, `/g_`, `/gw_`). Остальные команды (`/status` и другие) доступны через меню бота.
- **Файлы и картинки** хаб не отправляет (графики текстовые).
- **Опрос событий (long polling)** документация MAX считает пригодным в основном для разработки и рекомендует webhook.
  Для одного хаба с небольшим числом пользователей опроса достаточно; webhook можно добавить позже (у хаба уже есть
  публичный HTTPS-адрес).
- **Проверено на поддельном API.** Код проверен тестами с имитацией API MAX. Первый запуск с настоящим токеном стоит
  проверить вручную: `/id`, `/start`, `/status`, затем тревога.

## Пользователи хаба

Хаб может обслуживать не только владельца, но и приглашённых пользователей. Пользователь работает в **общем боте хаба**
(@HubSentryAgent): добавляет сайты и серверы, получает тревоги, сводки, свою страницу статуса. Хаб различает людей по
их Telegram-аккаунту, чужих проектов никто не видит. По желанию пользователь подключает **свой** бот со своим именем
(`/mybot`).

## Как подключается пользователь

1. Владелец в своём боте отправляет `/invite заметка` (например, `/invite Иван из Garage`). Бот показывает одноразовый
   код вида `ABCDE-FGHJK` и ссылку на общего бота.
2. Владелец передаёт человеку код и ссылку.
3. Человек пишет общему боту, присылает код и сразу видит приветствие. В этом же чате работают все команды
   пользователя: `/add` добавляет проект и выдаёт токен, `/install` объясняет, как поставить агент на сервер (ссылка на
   загрузчик и его контрольная сумма), `/status`, `/help` и остальные. Сюда же приходят его тревоги.
4. Владельцу приходит «🆕 Новый пользователь хаба».

### MAX

То же самое работает в MAX (`/invite` показывает ссылки на обоих ботов, в ссылке MAX код уже вшит): см. раздел «Хаб в MAX» в этом файле.

### Свой бот (по желанию)

`/mybot` в общем боте: человек создаёт бота в @BotFather и присылает токен, хаб проверяет его (getMe) и дальше
работает через этот бот (его имя, аватарка; проекты и настройки те же). `/mybot off` в общем боте возвращает всё обратно.
Создать бота за человека хаб не может: в Telegram новых ботов создаёт только @BotFather по командам живого аккаунта.

## Один бот для владельца и пользователей

Отдельный бот владельца не нужен. Если в `.env` задан `REGISTRATION_BOT_TOKEN`, а `TELEGRAM_BOT_TOKEN` пуст (или совпадает с ним), общий бот узнаёт владельца по Telegram-аккаунту из `TELEGRAM_CHAT_IDS`: ему показывается полное меню и доступны все команды (`/web`, `/shutdown`, `/invite`, `/tenants`), а тревоги владельца приходят в тот же бот. Остальные аккаунты видят только пользовательские команды и работают со своей базой. Узнают по числовому ID аккаунта, который подделать нельзя, а не по тексту сообщения. Владельцу нужно один раз нажать «Запустить» в общем боте, иначе Telegram не даст боту написать ему первым.

## Управление (только владельцу)

| Команда | Что делает |
| --- | --- |
| `/invite [заметка]` | новый одноразовый код приглашения |
| `/tenants` | пользователи: бот, сколько проектов из лимита, заметка из приглашения |
| `/tenant N limit 20` | лимит проектов пользователя (по умолчанию 10) |
| `/tenant N off` | отключить: бот пользователя перестаёт отвечать, проверки не идут, агенты получают 401; данные сохраняются |
| `/tenant N on` | включить снова |
| `/tenant N delete` и `/tenant N delete yes` | полностью удалить пользователя (сначала бот просит подтверждение): стираются его база и проекты, ему приходит сообщение, использованный код гаснет; чтобы вернуться, нужен новый код приглашения |

Все команды владельца собраны в `/admin_help`, в общую справку и меню бота они не попадают.

У пользователей нет служебных команд владельца: `/shutdown`, `/web`, `/invite`, `/tenants`, `/tenant`. Проверку адреса
пользователь может задать не чаще раза в минуту.

## Как устроено

- **Изоляция.** У каждого пользователя своя база `data/tenants/<номер>.sqlite` с той же схемой: проекты, тревоги,
  история, настройки, страница статуса. Код проверок и бота работает с базой конкретного пользователя, поэтому чужие
  проекты не видны в принципе, даже при ошибке в каком-то запросе. Реестр пользователей и коды приглашения хранятся в
  базе владельца `hub.sqlite`.
- **Агенты пользователей** присылают данные на тот же адрес хаба. Хаб находит проект по токену у владельца или у
  пользователей и пишет в базу того, чей это проект.
- **Токены своих ботов пользователей** (если подключили через `/mybot`) хранятся только зашифрованными (AES-256-GCM). Ключ `HUB_SECRET_KEY` лежит в `.env`
  хаба, не в базе. **Без этого ключа боты пользователей не запустятся**: он входит в зашифрованную копию `.env` в
  ночном бэкапе, держите копию и у себя (`Desktop\hub-secrets\hub.env`).
- **Коды приглашения** хранятся только в виде хэша; подбирать их нельзя (5 попыток в час).
- **Бэкап:** ночной бэкап снимает базы всех пользователей одним архивом `hub-backups/tenants/tenants_<дата>.tar.gz.enc`
  (зашифрован тем же паролем, что и база владельца), хранится 30 дней.

## Настройка

В `.env` хаба:

```
REGISTRATION_BOT_TOKEN=…   # токен общего бота для пользователей
HUB_SECRET_KEY=…           # openssl rand -base64 32, НЕ ТЕРЯТЬ
HUB_PUBLIC_URL=https://uptime.profium.pro
```

Без `REGISTRATION_BOT_TOKEN` или `HUB_SECRET_KEY` регистрация выключена, хаб работает как раньше.

## Риски, о которых нужно помнить

- **Прокси Telegram.** Все запросы к Telegram, в том числе общего бота и своих ботов пользователей, идут через `TELEGRAM_API_BASE`
  (сейчас `mon.profium.pro`, его обслуживает сторонний разработчик). Тот, кто управляет прокси, технически может увидеть
  токены ботов и тексты уведомлений пользователей. Для надёжности нужен свой прокси (см. раздел о прокси в этом файле).
- **Загрузчик агента.** Агент, установщик и `hub.sh` подписаны ключом владельца, подменить их через хаб нельзя. Сам `hub-install.sh` не подписан: пользователь скачивает его из открытого репозитория https://github.com/f1est0/hub-installer (хаб и прокси в этом пути не участвуют) и сверяет контрольную сумму. Подпись выпуска действует 60 дней, за 14 дней хаб напоминает продлить (`node clients/kit/publish.mjs`).
- **Домашний Pi.** Если у Pi пропадёт интернет или электричество, мониторинг перестанет работать у всех пользователей.
  Для настоящего публичного сервиса хаб лучше перенести на VDS (код при этом не меняется).

## Агент сервера

Агент ставится на сервер (VDS, Raspberry Pi) и раз в 5 минут отправляет в хаб состояние машины. Нужны только `sh` и
`curl`, запускать от root (иначе он не увидит Docker, журнал SSH и часть проверок безопасности). Агент заодно служит
сигналом «я жив»: если он замолчал, хаб сообщит, что сервер не выходит на связь (для такого проекта ставят
`--heartbeat 900`, то есть три пропущенных отправки).

Текущая версия: **11**. Версия каждого сервера видна в карточке (`/project код`); если она старее, там же подсказка
обновить.

## Установка и обновление

Владельцу сервера отдаётся один файл `hub-install.sh` с инструкцией (`clients/kit/ADMIN-README.md`):

```bash
sudo sh hub-install.sh       # меню: установка, проверка токена, обновления, удаление
```

Установщик проверяет токен, ставит агента в `/opt/hub-agent.sh`, токен в `/etc/hub-agent.env` (права 600) и cron
`/etc/cron.d/hub-agent`. Обновления подписаны ключом владельца хаба: загрузчик проверяет подпись манифеста и sha256
файлов, откат на старую версию отклоняется. Автообновление (пункт 8 меню) проверяет обновления раз в сутки ночью.
Подробно о подписи и публикации: [clients/kit/README.md](../clients/kit/README.md).

Посмотреть, что агент отправит, без отправки: `sudo sh /opt/hub-agent.sh --print` (нужны `HUB_URL` и `HUB_TOKEN`, их
даёт `set -a; . /etc/hub-agent.env; set +a`).

## Опасные порты: проверка снаружи

Агент сообщает, какие порты сервер слушает на внешних адресах (`listenPorts`, по `ss`) и какие публикует Docker
(`dockerPorts`, с v5: Docker открывает их в обход ufw). Если среди них есть порты баз данных и служебных сервисов
(PostgreSQL, MySQL, Redis, MongoDB, ClickHouse, Elasticsearch, Docker API, etcd, RabbitMQ, Kibana, Prometheus и др.),
хаб сам пробует подключиться к ним по адресу сервера. Для Redis отправляется `PING`, для Docker API `GET /version`:
так видно, пускают ли они без пароля. Проверка идёт сразу при изменении списка портов или адреса и раз в 6 часов.
Порты, открытые намеренно, задаются `/set код --open 3129,8443`.

## Что агент не отправляет

Содержимое файлов и строки логов, пароли, сами ключи SSH, переменные окружения, аргументы команд, содержимое трафика,
адреса, с которыми сервер соединяется (только их число). Имена файлов только в папках, которые задал владелец хаба
(`--fresh`), и то лишь путь самой папки. Самый новый файл в этих папках агент с версии 10 открывает для проверки целостности (`gzip -t`, `tar -t`, `pg_restore` и подобное), но наружу уходит только результат «целый» или «повреждён». Для баз данных уходят только числа, пароли агент не хранит. Агент не открывает портов и не принимает команд.

## Поля отчёта (`POST /api/v1/metrics`)

Все поля необязательные, хаб проверяет диапазоны и отбрасывает неизвестные (лимит тела 16 КБ). Точный формат:
`parseMetrics` в [src/metrics.ts](../src/metrics.ts).

| --- | --- |
| 1 | `disks` [{`mount`, `usedPct`}], `memPct`, `load1`, `cpus`, `tempC`, `uptimeS`, `pendingUpdates`, `rebootRequired`, `containers` [{`name`, `state`}] |
| 2 | `agentVersion`, `swapPct`, `oomKills`, `failedUnits`, `disks[].inodesPct`, `containers[].restarts`, `containers[].health` |

| 4 | `reach` [{`host`, `ok`, `ms`, `reason`}], `reachSkipped` |
| 5 | `cpuTotal`, `cpuIdle`, `cpuSteal` (накопительные счётчики, загрузку считает хаб), `topCpu` [{`name`, `pct`}], `topMem` [{`name`, `mb`}], `dockerPorts`, `containers[].cpuPct`, `containers[].memPct`, `containers[].memMb` |

## История

Хаб хранит историю показателей (средние за 5 минут 2 суток, за час 35 суток, за сутки 400 суток): процессор, steal,
нагрузка, память, swap, самый заполненный диск, температура, iowait, трафик, соединения. Из неё карточка показывает
строку «За сутки».
